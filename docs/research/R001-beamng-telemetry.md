# R001: BeamNG passive telemetry capability

Question: Can ACNG read useful vehicle/wheel state without changing stock physics?

Build: BeamNG.drive 0.39.4.0.20972, Steam build 24617469. Local sources: `lua/vehicle/wheels.lua`, `sensors.lua`, `electrics.lua`, `extensions/telemetryLogger.lua`, `protocols/outgauge.lua`, `lua/common/extensions.lua`, `lua/ge/extensions/core/modmanager.lua`. References are read locally; source files are not copied into ACNG.

Procedure: backed up primary settings/vehicle configs with Universal Modder; launched independent user profile; deployed unique modScript + GE control extension + Vehicle Lua observer. Stationary stock pickup smoke, then stock ETK `kc6_360_M` acceleration/braking pilot on Small Grid. Master OFF during capture; no dynamics modules exist. Loopback receiver stored JSONL. Native channels retain native signs/units where not fully calibrated.

Evidence: `docs/test-results/smoke-001.json`, `b001-pilot-events.json`, corresponding screenshots and pilot result JSONs. Raw captures live in ignored `telemetry/runs/`; logs in workspace `work/`. Pickup capture: 244 samples, zero gaps/malformed/out-of-order, 8.4965 simulation seconds, 28.6 Hz observed, max gap 0.0500 s. ETK capture: 792 samples, zero gaps/malformed/out-of-order, max interval 0.0335 s. SHA-256 of ETK JSONL: `ea3fac1b76c09c799e56e7c546552f583849b46cc7bdc7078ac98556fda53a8d`.

Observed: speed, position/velocity, native acceleration sensors/yaw, controls, RPM/gear and four identified wheels arrive. Pressure, raw load, rotational speed and native slip velocities vary during motion. Late stationary pickup sensor Z averages -9.8094, suggesting m/s² rather than units of g, and demonstrating gravity/non-inertial convention matters. Native tire average/core readings are approximately 288.15 and remain exactly constant per wheel throughout the ETK pilot. This does NOT establish a working dynamic tire thermal/grip model. UI/native implementation and longer heat experiments must determine whether getters represent active simulation, ambient fallback, or a disabled path.

Uncertainty: native slip velocity is neither calibrated slip ratio nor slip angle. Yaw sign, acceleration frame/sign, effective radius, thermal scale and steering angle versus normalized input need controlled tests. Pressure getter appears absolute Pa from local wheel usage; pressure changed under loading, so changes cannot yet be attributed to heat. Actual graphics cadence limits capture rate. Raw wheel load smoothness/contact semantics need damage/airborne tests. UDP is lossy by design; sequence counters make observed losses visible but are not a physics-step recorder.

Conclusion: passive runtime telemetry path works for measured channels on two stock vehicles, with successful master ON/OFF and telemetry detach. Confidence high for delivery/lifecycle, medium for field interpretations, low for thermal behavior. No tire-grip or AC-equivalence claim.

Implementation: keep observer independent of master for baselines. Use native thermal/pressure capability as an investigation starting point, not proof that physics features already exist. Calibrate coordinates and units before comparison. Avoid stock file overrides. Official extension/packing/protocol guidance: [Extensions](https://docs.beamng.com/modding/programming/extensions/), [Packing](https://docs.beamng.com/modding/mod-support/mod_packing/), [Protocols](https://www.docs.beamng.com/modding/protocols/). Native data influence possibilities should be assessed against [Pressure Wheels](https://docs.beamng.com/modding/vehicle/sections/wheels/) before considering hooks.
